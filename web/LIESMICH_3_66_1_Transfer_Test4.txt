Allmiibo Dateimanager 3.66.1 · Transfer Test 4

Deutsch

Entpacke die gesamte ZIP in einen eigenen Ordner. Starte dort
Start-Dateimanager.cmd und öffne den Dateimanager in Chrome oder Edge.
Oben bei der Browserversion steht „3.66.1 · Transfer Test 4“.
Der lokale Start setzt Python 3.8 oder neuer voraus.
Stop-Dateimanager.cmd beendet den lokalen Server.

Zum Direktstart mit sichtbarem Serverfenster verwende
Start-Dateimanager-Direkt.cmd. Öffne die dort angezeigte Adresse
im Browser. Strg+C im Serverfenster beendet diesen Direktstart.

Ordner werden beim Erstupload in geeigneten Gruppen angelegt. Das Gerät
bestätigt die Schreibvorgänge. Beim Abschluss genügt eine kurze Abfrage.
Bei einer Unterbrechung prüft der Dateimanager unsichere Schreibvorgänge
vor dem Fortsetzen erneut. Über den Ordnervergleich kannst du jederzeit
einen vollständigen SHA-256-Vergleich starten.

Mit denselben 1.081 Dateien und 658.806 Nutzbytes sank die Zahl der
Ordnerabfragen beim Upload in einen vorhandenen Ordner von 795 in Test 3
auf 104. Auf der originalen Speicher-Engine stimmten nach erneutem
Einbinden alle Inhalte und Metadaten überein, auch bei einer verlorenen
Antwort nach dem 33. kleinen Schreibvorgang. Die Bluetooth-Uploadzeit
für diese Testversion muss noch am LCD gemessen werden.

Der übernommene Lesepfad brauchte an einem LCD unter Windows Chrome für
24 Dateien (12.960 Byte) im Mittel 9,08 Sekunden. Mochi brauchte für
dieselben Dateien 17,28 Sekunden. Das entspricht rund 47 % weniger Zeit.

Die beiliegende LCD-Firmware ist DE4.1 / App678. Der DFU-Updater nutzt die
in Test 2 geprüfte Wortausrichtung. Bestätigt Z21 das vollständige
142-Byte-Init-Paket, sendet er anschließend bis zu 140 Byte je Datenpaket.
Nach einer ersten bestätigten Gerätequittung kann er bis zu acht Schreibvorgänge
mit einer gemeinsamen CRC-Prüfung bündeln. Im Z21-Modell sank die Zahl der
GATT-Schreibvorgänge für App678 von 5.500 auf 3.200. Eine Windows-DFU-Zeit
über Funk ist noch offen.

English

Extract the entire ZIP to its own folder. Run Start-Dateimanager.cmd and
open the file manager in Chrome or Edge. The browser version at the top
reads “3.66.1 · Transfer Test 4”. Starting locally requires Python 3.8
or later. Stop-Dateimanager.cmd stops the local server.

For a foreground server, run Start-Dateimanager-Direkt.cmd, open the
address printed in its window, and press Ctrl+C there when finished.

For initial uploads, the manager creates eligible folders in groups.
The device acknowledges each write. A short status check finishes the job.
After an interruption, the manager rechecks uncertain writes before
resuming. Use the folder comparison for a complete SHA-256 content check.

With the same 1,081 files and 658,806 payload bytes, the number of folder
listings for an existing destination dropped from 795 in Test 3 to 104.
All file contents and metadata matched after remounting the original
storage engine, including after a lost reply on the 33rd small write.
The Bluetooth upload time for this test version still needs to be measured
on an LCD.

On one LCD, the same read implementation on Windows Chrome took an average
of 9.08 seconds for 24 files (12,960 bytes). Mochi took 17.28 seconds for
the same files. That is about 47% less elapsed time.

The bundled LCD firmware is DE4.1 / App678. The DFU updater uses the word
alignment tested in Transfer Test 2. When Z21 confirms the full 142-byte
init packet, the updater subsequently sends up to 140 bytes per data write.
After the first device acknowledgement it can group up to eight writes per
CRC check. The Z21 model needed 3,200 GATT writes for App678, down from
5,500. Windows firmware-update timing over Bluetooth is pending.
