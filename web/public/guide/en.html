Update your Allmiibo

Update an LCD Allmiibo, move your collection to Packed LittleFS and check whether a system update is suitable for your device.

Read the device information first

Open the file manager. On the device, open BLE file transfer, press Connect in the browser and select your Pixl.js. If you have two devices, leave only the intended one advertising.

  1. Identify your hardware and versions

    Check the physical display variant. The applications linked here are for the LCD model. The file manager shows the browser software and the device firmware separately. Under Device & diagnostics, read the bootloader and SoftDevice information to see the counters, radio firmware and validation results.

  2. Identify the storage layout

    Open Backup → LittleFS: migration & restoration → Read storage status. If E: already uses Packed LittleFS (PFS1) and the import is complete, proceed to the app update. If the import is pending, resume it with its original saved ZIP.

  3. Resolve missing information

    Older applications such as DE3.8 may omit bootloader or storage information. Establish the LCD board, current layout and intended package before making changes. OLED boards, ordinary upstream LittleFS and a failed query require separate identification.

Flash the application over Bluetooth

For a compatible LCD with a completed PFS1 setup, DE3.65 / 637 is the stable release. DE3.73 / 646 is the optional test release. It fixes long presses on Back in the slot list and restores the last figure selection across favourites pages. The target configuration uses Z19 and Nordic S112 7.3.0. If diagnostics show Z19 and S112 7.3.0 (0x0126), use the application-only ZIP for DE3.73. If you need a system component, check the full package requirements.

  1. Back up your collection

    Keep a current backup. In the file manager, open Files → E:/, then Backup → Back up folder (ZIP). Save the finished ZIP to Downloads. A first-time storage migration uses the full Raw128 migration backup.

  2. Select the application

    Use Update in the file manager or open the Web DFU page. Choose your LCD version. On Android, Open in nRF DFU (Android) opens the selected package in the installed Nordic app. To update in the browser, choose Load and check package. Both application ZIPs are also available for download below.

  3. Select the device in update mode

    Disconnect file transfer and other connected apps. On the Allmiibo open Settings → Firmware update. In the Nordic app select pixl dfu and start the transfer. On the Web DFU page the transfer starts when you choose Select DFU device and transfer → pixl dfu. Keep the device within range and the phone awake.

  4. Check the restart

    Wait for the normal menu. Open BLE file transfer, reconnect to Pixl.js in the file manager and read back the device version. Open a familiar folder and figure. This package updates the application and retains your existing PFS1 collection.

Migrate from SPIFFS to Packed LittleFS

This procedure sets up drive E: once. It requires a preparation and recovery path qualified for your exact hardware. Flashing a new application onto a device running DE3.8 or DE3.16 by itself does not convert its storage.

  1. Keep the original and full backup

    Save a separate copy of the accessible E:/ drive before preparation. The migration assistant requires all 128 attribute bytes for every entry (Raw128). On confirmed SPIFFS, DE3.30-PREP / 600 (preparation ZIP) exposes these attributes. It requires a compatible LCD, Nordic Secure DFU with the matching signing key, and S112 with FWID 0x0103 or 0x0126. For first installation, the current application counter must be below 600. If DE3.30-PREP / 600 is already running, proceed to the backup. For any other application at counter 600 or higher, establish a compatible backup path first. After saving the first backup, transfer the intact preparation ZIP in DFU mode with nRF Device Firmware Update. Reopen Bluetooth file transfer in PREP after restart. A device already on PFS1 can keep its current compatible firmware.

  2. Compare the saved ZIP with the source

    Under Backup → LittleFS: migration & restoration, choose Create full backup → Save ZIP → Select the saved ZIP again → Verify complete source. Wait for the complete comparison to match. Keep the ZIP and use the same browser and file-manager address for its stored verification receipt.

  3. Check capacity before erasing

    DE3.71 / 643 is outside the qualified capacity profiles. For DE3.73, choose the capacity profile with application counter 646 and select Simulate LittleFS capacity locally. The simulation includes temporary blocks and a free-space reserve. If the profile is unavailable, a check fails or space is insufficient, keep the current storage intact.

  4. Check and explicitly initialize the target

    After the capacity check passes, use the target application or, if required for your installed system, the full LCD package. Reconnect the same Allmiibo. Choose Check target device. Once the backup, source comparison and capacity check pass, you can confirm Initialize storage …. This erases the previous contents of E:. Next, Confirm backup for import … binds the import to this exact ZIP.

  5. Restore and run one complete final comparison

    Choose Restore / resume all user entries, then Finish import after a fresh complete verification. This compares files, folders and raw attributes. Wait for Import completion acknowledged by the device. Choose Explicitly restart device …, then check your folders and a familiar figure.

  6. Resume an interrupted restoration

    Reconnect the same device in the same browser, reselect the identical saved ZIP and choose Restore / resume all user entries. A pending import already has an initialized volume. Restoring a large collection over Bluetooth can take many minutes.

Full package with bootloader Z19, S112 and App646

The bootloader receives updates and starts the application. The Nordic S112 SoftDevice provides the Bluetooth stack. An ordinary application update on a compatible system needs only the application package.

  1. Compare the installed components

    Read the bootloader and SoftDevice data under Device & diagnostics. Identify Z19 using bootloader counter 19 together with the published boot-region hash. S112 7.3.0 reports firmware ID 0x0126. If these already match your intended system, a repeat flash is unnecessary. Z19 reference values.

  2. Check the starting firmware and backup

    This package requires a compatible LCD Allmiibo with an nRF52832 and a working Nordic Secure DFU bootloader that accepts this project’s signing key. The checked layout has 512 KiB internal flash, 64 KiB RAM and the bootloader at 0x77000. Supported starting S112 firmware IDs are 0x0103 (7.2.0) and 0x0126 (7.3.0). The installed bootloader counter must be below 19. A bootloader with counter 19 or higher rejects this system update. OLED devices, unknown signing keys and devices without a working DFU bootloader need a separate installation procedure. The layout places the MBR parameter page at 0x7E000 and DFU settings at 0x7F000. Check the device information and back up your collection first. For SPIFFS, complete the Raw128 backup, source comparison and capacity check before the update. The firmware ZIP does not set up file storage.

  3. Transfer both stages with Android

    Download the full DE3.73 package (ZIP). Keep the ZIP intact. Disconnect the file manager and open Settings → Firmware update on the device. In nRF Device Firmware Update, select the ZIP and your pixl dfu. The app transfers S112 7.3.0 and bootloader Z19 first, then App646. Keep the Nordic app open through the intermediate restart until the second stage completes. The web updater supports the application-only ZIP.

  4. Read back the installed versions

    Reconnect to Pixl.js in the file manager after the final restart. Check for 2.22.0-DE3.73 / 646, bootloader counter 19 with the Z19 boot-region hash, and S112 7.3.0 with FWID 0x0126. If storage migration is pending, continue with the migration assistant and your verified backup.

If a step stops

  • The backup button is grey

    Open Files and select the root E:/ first. Connecting to a device alone does not select a folder.

  • The device does not appear

    For file management, use BLE file transfer and select Pixl.js. For updates, use Firmware update and select pixl dfu. Disconnect other browsers and phone apps using the device.

  • An application transfer was interrupted

    When pixl dfu reappears, select the same device and the same application ZIP. The web updater reads the saved position and checksum. Depending on the device's confirmed state, it resumes or starts again. For an interrupted system update, use the recovery procedure for that package in its supported client.

Programs and downloads

Use Chrome on Android or a Web Bluetooth browser such as Chrome or Edge on a laptop. The file manager itself runs in your browser. Updating the website requires no firmware flash.

System updates on a PC with a Nordic radio adapter

For a compatible signed system package, nRF Util supports transfers over Bluetooth LE on a PC with nrfutil nrf5sdk-tools dfu ble. This requires a separate Nordic radio adapter connected over USB, such as the nRF52840 Dongle (PCA10059) or a compatible Nordic development kit. The laptop’s built-in Bluetooth alone cannot run this procedure. For application updates you can use the web updater. For a compatible combined package on a phone, follow the Android steps. Nordic’s guide to DFU over Bluetooth LE on a PC.
