DE3.17 LCD runtime diagnostics (application-only; optional protocol extension)
============================================================================

INFO 0x06 accepts only an empty request with status=0 and chunk=0. A supported
build returns status=0 and exactly64 logical payload bytes. Ordinary transport
fragmentation applies, including ATT MTU23. No existing command's status or
payload format changes. An unsupported firmware/build returns a normal error;
the companion must treat this command as optional and continue without it.

The command observes RAM only. It does not start DFU, disconnect, change MTU,
write/repair files, reset counters or store names, paths, addresses or contents.
Counters survive Bluetooth reconnects but reset on a processor restart (also
normal System OFF wake). No persistent crash recorder is introduced.

All numeric fields are little-endian. Unavailable sampled minima and static
stack reservation use0xFFFFFFFF; unavailable current-pool fields are0 and bit0
is clear. Reserved fields must be ignored by clients. Unsupported is not zero.

Local cause:0 none observed;1 bounded work queue overflow;2 fragment/reply
timeout;3 malformed protocol packet;4 live-session transmission failure;
5 GATT client timeout;6 GATT server timeout. The local cause and HCI reason
are separate historical observations and need not refer to the same event.
An old/cancelled response must not overwrite an earlier queue cause with a
secondary transmission error. No timestamp or link identity is collected.

VFS errors preserve the original VFS enum: -1 failure, -2 memory, -3 EOF,
-4 exists, -5 path/name length, -6 unavailable drive, -7 corruption,
-90 missing object, -91 no space, -99 unsupported. Additional diagnostic-only
codes: -1000 invalid request, -1001 invalid transfer state. Successful commands
do not erase the last failure. EOF at normal directory end is not a failure.
Counts are observations, not an exact count of failed user operations.

Memory interpretation
---------------------
The existing TLSF pool walker samples current free space on explicit monitoring
or Info0x06 queries. Its minima are only minima of those samples, not continuous
free-RAM watermarks. Each allocation/free/reallocation additionally accounts
actual tlsf_block_size() in O(1) to track the maximum observed allocated payload
balance after completed MUI allocator calls. Failed realloc preserves the old
block/accounting; realloc(p,0) releases it. A moving realloc can temporarily
hold both old and new TLSF blocks internally; that transient overlap is not
measured. This is not an uninterrupted physical allocator peak and also excludes
allocator metadata, static RAM, the SDK heap and stack. It cannot be subtracted
from all nRF52832 RAM to claim a safety reserve.

From DE3.59 onwards the first action in main marks unused aligned words below
the active Main Stack Pointer (MSP), within the linker's reserved stack. On
an INFO 0x06 query, the firmware counts the contiguous intact words from the
bottom, capped at the current MSP and the previous low-water observation.
Zero means the marker at the stack bottom was touched, or the MSP reached
the bottom. A missing/unsupported result keeps bit3 clear. No ongoing polling
or flash writes are involved. The largest scan is 2048 RAM words (8 KiB).

The watermark includes writes from interrupts and S112 on the shared MSP
after marking. It excludes bootloader/early SDK activity. Untouched reserved
frames and writes that happen to restore their markers may be missed. The
result is approximate and cannot by itself justify reducing the reservation.
https://docs.nordicsemi.com/r/bundle/sds_s112/page/sds/s1xx/mem_usage/mem_resource_reqs.html

Implementation footprint: runtime diagnostic state is compile-time bounded to
56 RAM bytes; no dynamic diagnostic allocation, persistent writes or paths.
Critical regions copy/update only the small counters/state, never walk TLSF.
The module is enabled only for the LCD application build; radio, NFC pins,
SoftDevice, bootloader, settings layout and figure data are unchanged.

Limited upstream optimization
-----------------------------
Reviewed primary source: https://github.com/solosky/pixl.js/pull/468 (still WIP).
The progress-bar expression already produces float; ceilf avoids converting it
to double before rounding. Within screen bounds its rendered integer is the
same. DE3.16 had already removed forced floating-point printf linking. LTO,
global logger disabling, crypto trimming, packed DB ABI and stack painting are
not imported. Flash savings must be measured on the final ARM build, not copied
from the upstream PR's combined figures.

Validation boundary
-------------------
test_runtime_diag.py exercises actual diagnostic/TLSF/MUI/DF/queue C code with
mocked VFS and Nordic notification endpoints at simulated ATT23/185/250. The
DE3.16 control must return unsupported; deliberate counter-wrap, missing
allocation-failure and false-stack-measurement mutations must compile and fail
assertions. Existing BLE SDK lifecycle tests cover the actual HCI/GATT hooks.
These tests do not prove real radio timing, physical heap/stack margin, NFC
compatibility or hardware endurance. Tybalt/Sprocket remains unresolved. No
historically blocked supplementary AmiiboLink check is included.
