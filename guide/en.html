Read the device information first

Open the file manager. On the device, open BLE file transfer, press Connect in the browser and select your Pixl.js. If you have two devices, leave only the intended one advertising.

  1. Identify your hardware and versions

    Check whether your device has an LCD or OLED display. For OLED, open the OLED preview instructions. The file manager shows the browser software and the device firmware separately. On the LCD, under Device & diagnostics, read the bootloader and SoftDevice information to see the counters, radio firmware and validation results.

  2. Identify the storage layout

    On an LCD, open Backup → LittleFS: migration & restoration → Read storage status. If E: already uses Packed LittleFS (PFS1) and the import is complete, proceed to the app update. If the import is pending, resume it with its original saved ZIP.

  3. Resolve missing information

    Older applications such as DE3.8 may omit bootloader or storage information. Identify the display variant, installed firmware and storage layout before choosing a package.

Regular app update DE4.2 / App680

The current normal LCD firmware is DE4.2 / App680. Use the app-only update for an nRF52832 LCD with Packed LittleFS (PFS1) already set up, bootloader Z21, and S112 7.3.0 (FWID 0x0126). This keeps the installed bootloader and radio software.

Download the DE4.2 / App680 LCD app ZIP for your phone. If the device already runs DE4.2 / 680, its application is current. If its application counter is higher, keep the newer firmware.

For a compatible LCD with an older system, see the Android full package with S112 7.3.0, Z21 and App662 and check its requirements first. Afterwards install normal App680 as a separate application update.

  1. Back up your collection

    Keep a current backup. In the file manager, open Files → E:/, then Backup → Back up folder (ZIP). Save the finished ZIP to Downloads. A first-time storage migration uses the full Raw128 migration backup.

  2. Select the application

    Use Update in the file manager or open the Web DFU page. Choose DE4.2 / App680. On Android, Open in nRF DFU (Android) opens the selected package in the installed Nordic app. To update in the browser, choose Load and check package.

  3. Select the device in update mode

    Disconnect file transfer and other connected apps. On the Allmiibo open Settings → Firmware update. In the Nordic app select pixl dfu and start the transfer. On the Web DFU page the transfer starts when you choose Select DFU device and transfer → pixl dfu. Keep the device within range and the phone awake.

  4. Check the restart

    Wait for the normal menu. Open BLE file transfer, reconnect to Pixl.js in the file manager and check for device version 2.22.0-DE4.2-b2 and application counter 680. Open a familiar folder and figure. This package updates the application and retains your existing PFS1 collection.

Migrate an LCD from SPIFFS to Packed LittleFS

This procedure sets up drive E: once. It requires a preparation and recovery path qualified for your exact hardware. Flashing a new application onto a device running DE3.8 or DE3.16 by itself does not convert its storage.

  1. Keep the original and full backup

    Save a separate copy of the accessible E:/ drive before preparation. The migration assistant requires all 128 attribute bytes for every entry (Raw128). On confirmed SPIFFS, DE3.30-PREP / 600 (preparation ZIP) exposes these attributes. It requires a compatible LCD, Nordic Secure DFU with the matching signing key, and S112 with FWID 0x0103 or 0x0126. For first installation, the current application counter must be below 600. If DE3.30-PREP / 600 is already running, proceed to the backup. For any other application at counter 600 or higher, establish a compatible backup path first. After saving the first backup, transfer the intact preparation ZIP in DFU mode with nRF Device Firmware Update. Reopen Bluetooth file transfer in PREP after restart. A device already on PFS1 can keep its current compatible firmware.

  2. Compare the saved ZIP with the source

    Under Backup → LittleFS: migration & restoration, choose Create full backup → Save ZIP → Select the saved ZIP again → Verify complete source. Wait for the complete comparison to match. Keep the ZIP and use the same browser and file-manager address for its stored verification receipt.

  3. Check capacity before erasing

    Choose the target firmware DE4.2-b2 / 680, then click Simulate LittleFS capacity locally. The simulation includes temporary blocks and a free-space reserve. If the profile is unavailable, a check fails or space is insufficient, keep the current storage intact.

  4. Check and explicitly initialize the target

    After the capacity check passes, use the qualified DE4.2 / App680 target. If your device needs the full LCD package, install that package first, followed by App680. Reconnect the same Allmiibo. Choose Check target device. Once the backup, source comparison and capacity check pass, you can confirm Initialize storage …. This erases the previous contents of E:. Next, Confirm backup for import … binds the import to this exact ZIP.

  5. Restore and run one complete final comparison

    Choose Restore / resume all user entries, then Finish import after a fresh complete verification. This compares files, folders and raw attributes. Wait for Import completion acknowledged by the device. Choose Explicitly restart device …, then check your folders and a familiar figure.

  6. Resume an interrupted restoration

    Reconnect the same device in the same browser, reselect the identical saved ZIP and choose Restore / resume all user entries. A pending import already has an initialized volume. Restoring a large collection over Bluetooth can take many minutes.

App680 is the default target for a new migration. Resume an import started on App678 or earlier with the same ZIP and its original profile. An LCD that already uses PFS1 can install App680 directly.

LCD full package for Android

DE3.89 / App662 with bootloader Z21 and S112 7.3.0

The full package updates the Nordic S112 radio software and bootloader first, then the LCD application. Open Device & diagnostics to read the installed versions and memory addresses.

  • Full update to Z21 · For an nRF52832 LCD (512 KiB flash, 64 KiB RAM) with working Nordic Secure DFU, the matching project signing key and the matching layout (bootloader 0x77000, MBR parameters 0x7E000, settings 0x7F000). The bootloader counter must be below 21. Supported starting S112 firmware IDs are 0x0103 (7.2.0) and 0x0126 (7.3.0). The app requires PFS1 and an application counter of 662 or lower. This includes compatible older Z15 or Z17 devices. Download the DE3.89 / App662 full package with Z21 and S112 7.3.0 (ZIP).
  • Z21 · With PFS1 already set up and S112 7.3.0 installed, use the normal DE4.2 / App680 LCD app (ZIP). From Z19 or Z20, the matching full package first updates the bootloader to Z21. A device on Z21 can skip the system stage. If you have a newer bootloader or application, keep the newer version.

  1. Back up the collection

    Save a backup before updating. If migrating from SPIFFS, first complete the Raw128 backup, full source comparison and local capacity check. Storage migration is a separate step.

  2. Transfer the full package on your phone

    Save the intact ZIP to Downloads. Disconnect the file manager and open Settings → Firmware update on the LCD. In nRF Device Firmware Update for Android, choose the ZIP and pixl dfu. Keep the app open through the intermediate restart until both stages finish. The web updater supports the application-only ZIP.

  3. Check the installed versions

    After the final restart, reconnect to Pixl.js in the file manager. Expect 2.22.0-DE3.89 / App662, bootloader counter 21 with the Z21 boot region hash, and S112 7.3.0 with FWID 0x0126. The owner confirmed operation on one LCD. The device reported the expected SourceID. Resuming an interrupted Android system update on physical Z21 hardware still needs verification.

Send an image or video to the LCD

Open Images & video in file manager 3.67.0. Sending requires an LCD running DE3.100/App673 or newer and a browser with Web Bluetooth. Preview and player export also work without Bluetooth. OLED does not support this image receiver.

Choose Scrolling text, type your message and select a speed. Play the preview on your phone. Choose Send scrolling text with the LCD receiver connected, or export one pass as a player file. Turn on Loop in the LCD animation player for continuous playback.

  1. Prepare the preview

    Choose a local image/video file, drop one file onto the selection area, or choose Use demo. The file stays on your computer or phone and is not uploaded. Check the 128 × 64 monochrome preview. Set the image format, Rotation, light/dark threshold and inversion. Photo dot pattern can preserve tonal detail.

  2. Open and connect the receiver

    Disconnect file transfer at the top of the website, or remote control in its workspace. Open BLE image stream in the LCD main menu. Choose Connect image receiver on the website and select your device. Sending becomes available after the receiver confirms the connection.

  3. Start transmission explicitly

    Choose Send image, Send video or Send demo. Selecting a file and connecting alone do not send images. A still image is sent once; videos and the demo run until stopped. The initial 5 frames/s is a target. Actual rate depends on Bluetooth and image content; video may skip intermediate frames.

  4. Stop and return to normal controls

    Stop sending or Disconnect closes the browser connection. Hiding the page, changing workspace or a connection failure also stops transmission. It never resumes automatically. On the LCD, Left toggles information, Right inverts the display, and Center exits the receiver.

Image options are remembered on this device if the browser allows it. One local file up to 128 MiB remains available across workspace changes for up to 30 minutes after selection. Larger files can be used but must be selected again after changing workspace. Reloading or closing the page discards the remembered file. Reset restores the defaults and demo.

Save an animation for the device player

  1. Choose the clip

    Open Save for the animation player. Choose start and end for a video, or duration for the demo. Set frame rate under Playback. Check frame count and file size. Shorten the clip or reduce the frame rate if the result exceeds 1 MiB.

  2. Create and download the file

    Choose Create player file. Follow progress or cancel export. After successful completion, Save file becomes available. A still image creates a single-frame player file.

  3. Copy it to the device

    Transfer the completed BIN through Files to E:/player/. The normal free-space check still applies. Export itself writes nothing to the device. Open the animation player and select the file.

On App675, the player's file list offers Loop and Frame counter. Both start off and apply to the current player session. App675 also improves image-receiver redraw scheduling; the web sender remains compatible with App673+.

Your browser must be able to play the video, for example a supported MP4 or WebM file. GIF files are handled as still images. Hiding or leaving the page cancels an active export; incomplete files are not offered for download. Real video codecs, image appearance, Bluetooth transmission and player behavior on the LCD require separate physical acceptance.

If a step stops

  • The backup button is grey

    Open Files and select the root E:/ first. Connecting to a device alone does not select a folder.

  • The device does not appear

    For file management, use BLE file transfer and select Pixl.js. For updates, use Firmware update and select pixl dfu. Disconnect other browsers and phone apps using the device.

  • An application transfer was interrupted

    When pixl dfu reappears, select the same device and the same application ZIP. The web updater reads the saved position and checksum. Depending on the device's confirmed state, it resumes or starts again. For an interrupted system update, use the recovery procedure for that package in its supported client.

System updates on a PC with a Nordic radio adapter

For a compatible signed system package, nRF Util supports transfers over Bluetooth LE on a PC with nrfutil nrf5sdk-tools dfu ble. This requires a separate Nordic radio adapter connected over USB, such as the nRF52840 Dongle (PCA10059) or a compatible Nordic development kit. The laptop’s built-in Bluetooth alone cannot run this procedure. For application updates you can use the web updater. For a compatible combined package on a phone, follow the Android steps.
