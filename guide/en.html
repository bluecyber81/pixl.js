Read the device information first

Open the file manager. On the device, open BLE file transfer, press Connect in the browser and select your Pixl.js. If you have two devices, leave only the intended one advertising.

  1. Identify your hardware and versions

    Check whether your device has an LCD or OLED display. For OLED, open the OLED preview instructions. The file manager shows the browser software and the device firmware separately. On the LCD, under Device & diagnostics, read the bootloader and SoftDevice information to see the counters, radio firmware and validation results.

  2. Identify the storage layout

    On an LCD, open Backup → LittleFS: migration & restoration → Read storage status. If E: already uses Packed LittleFS (PFS1) and the import is complete, proceed to the app update. If the import is pending, resume it with its original saved ZIP.

  3. Resolve missing information

    Older applications such as DE3.8 may omit bootloader or storage information. Identify the display variant, installed firmware and storage layout before choosing a package.

Use the new device test

  1. Settings → Device test starts with pixel/button information. Short Center advances to Remote control, with status and any SDK error.
  2. Short Center again opens Backlight test at 5% PWM. Left sets 5%, Right 100%; the pixel pattern stays the same. Set and PWM are the target and SDK readback, not measured physical brightness.
  3. Short Center returns to the information page; long Center exits from any page. Leaving or sleep restores the previous backlight value. The test saves no new setting; automatic dimming pauses during the light test.

Remote control and automatic screen photos

Exit file transfer/AmiiboLink. On the awake LCD select Settings → Remote → until off. In file manager 3.57.0 → Remote control → Allmiibo DE, connect and select Pixl.Remote again: the new firmware has its own remote address. Permission ends at power-off/restart.

Refresh screen automatically after button presses is optional and starts off. It reads one image after acknowledged Left/Center/Right/Back and combines quick sequences. Wait briefly during capture. There is no continuous polling or repeated key command. Disconnect or file handoff cancels pending images; firmware without screenshot support is not probed. Games may prevent capture. Manual refresh remains available.

Still to verify on hardware: all three test pages, visible backlight difference and restoration, remote discovery/buttons/photos, files, NFC, and sleep/wake. Computer checks do not replace this device acceptance.

Regular app update DE3.81 / App654

The stable LCD firmware is DE3.81 / App654. Use the app-only update for an nRF52832 LCD with Packed LittleFS (PFS1) already set up, bootloader Z19, Z20 or Z21, and S112 7.3.0 (FWID 0x0126). This keeps the installed bootloader and radio software.

Download the DE3.81 / App654 LCD app ZIP for your phone. If the device already runs DE3.81 / 654, its application is current. If its application counter is higher, keep the newer firmware.

For a compatible LCD with an older system, see the Android full package with S112 7.3.0, Z21 and App654 and check its requirements first.

  1. Back up your collection

    Keep a current backup. In the file manager, open Files → E:/, then Backup → Back up folder (ZIP). Save the finished ZIP to Downloads. A first-time storage migration uses the full Raw128 migration backup.

  2. Select the application

    Use Update in the file manager or open the Web DFU page. Choose DE3.81 / App654. On Android, Open in nRF DFU (Android) opens the selected package in the installed Nordic app. To update in the browser, choose Load and check package.

  3. Select the device in update mode

    Disconnect file transfer and other connected apps. On the Allmiibo open Settings → Firmware update. In the Nordic app select pixl dfu and start the transfer. On the Web DFU page the transfer starts when you choose Select DFU device and transfer → pixl dfu. Keep the device within range and the phone awake.

  4. Check the restart

    Wait for the normal menu. Open BLE file transfer, reconnect to Pixl.js in the file manager and check for device version 2.22.0-DE3.81 and application counter 654. Open a familiar folder and figure. This package updates the application and retains your existing PFS1 collection.

Install the DE3.87 OLED preview

For the nRF52832 Pixl.js OLED with a 128 × 64 SH1106, a compatible DFU bootloader and S112 7.2.0 (FWID 0x0103). Reference releases are cylin577 OLED v2.21.0 and v2.27.11. The app uses your existing SPIFFS or native LittleFS on supported 2, 4, 8 or 16 MiB flash chips.

Save a backup, check your collection and keep the previous OLED application ZIP.

Flash from your computer's browser

  1. Open and check the OLED package

    Open the OLED web DFU page in Chrome or Edge on a computer with Bluetooth and Web Bluetooth support. Check that Your device display shows OLED. Check DE3.87 OLED Test 6 / App86 and the device and S112 requirements above. Choose Load and check package.

  2. Select the DFU device and transfer

    Disconnect file transfer and other apps connected to the OLED. Open Settings → Firmware Update on the device. Click Select DFU device and transfer, then choose pixl dfu. LCD and OLED devices can share this DFU name, so select the OLED whose model you checked on the device. Keep it in range and leave the browser open until completion.

  3. Wait for the restart

    After the transfer, wait for the OLED menu to appear. Reconnect Bluetooth file transfer and check the version as described below.

Migrate an LCD from SPIFFS to Packed LittleFS

This procedure sets up drive E: once. It requires a preparation and recovery path qualified for your exact hardware. Flashing a new application onto a device running DE3.8 or DE3.16 by itself does not convert its storage.

  1. Keep the original and full backup

    Save a separate copy of the accessible E:/ drive before preparation. The migration assistant requires all 128 attribute bytes for every entry (Raw128). On confirmed SPIFFS, DE3.30-PREP / 600 (preparation ZIP) exposes these attributes. It requires a compatible LCD, Nordic Secure DFU with the matching signing key, and S112 with FWID 0x0103 or 0x0126. For first installation, the current application counter must be below 600. If DE3.30-PREP / 600 is already running, proceed to the backup. For any other application at counter 600 or higher, establish a compatible backup path first. After saving the first backup, transfer the intact preparation ZIP in DFU mode with nRF Device Firmware Update. Reopen Bluetooth file transfer in PREP after restart. A device already on PFS1 can keep its current compatible firmware.

  2. Compare the saved ZIP with the source

    Under Backup → LittleFS: migration & restoration, choose Create full backup → Save ZIP → Select the saved ZIP again → Verify complete source. Wait for the complete comparison to match. Keep the ZIP and use the same browser and file-manager address for its stored verification receipt.

  3. Check capacity before erasing

    Choose the target firmware DE3.81 / 654, then click Simulate LittleFS capacity locally. The simulation includes temporary blocks and a free-space reserve. If the profile is unavailable, a check fails or space is insufficient, keep the current storage intact.

  4. Check and explicitly initialize the target

    After the capacity check passes, use the target application or, if required for your installed system, the full LCD package. Reconnect the same Allmiibo. Choose Check target device. Once the backup, source comparison and capacity check pass, you can confirm Initialize storage …. This erases the previous contents of E:. Next, Confirm backup for import … binds the import to this exact ZIP.

  5. Restore and run one complete final comparison

    Choose Restore / resume all user entries, then Finish import after a fresh complete verification. This compares files, folders and raw attributes. Wait for Import completion acknowledged by the device. Choose Explicitly restart device …, then check your folders and a familiar figure.

  6. Resume an interrupted restoration

    Reconnect the same device in the same browser, reselect the identical saved ZIP and choose Restore / resume all user entries. A pending import already has an initialized volume. Restoring a large collection over Bluetooth can take many minutes.

LCD full package for Android

DE3.81 / App654 with bootloader Z21 and S112 7.3.0

The full package updates the Nordic S112 radio software and bootloader first, then the LCD application. Open Device & diagnostics to read the installed versions and memory addresses.

  • Full update to Z21 · For an nRF52832 LCD (512 KiB flash, 64 KiB RAM) with working Nordic Secure DFU, the matching project signing key and the matching layout (bootloader 0x77000, MBR parameters 0x7E000, settings 0x7F000). The bootloader counter must be below 21. Supported starting S112 firmware IDs are 0x0103 (7.2.0) and 0x0126 (7.3.0). This includes compatible older Z15 or Z17 devices. Download the DE3.81 / App654 full package with Z21 and S112 7.3.0 (ZIP).
  • Z19, Z20 or Z21 · With PFS1 already set up and S112 7.3.0 installed, use the DE3.81 / App654 LCD app (ZIP). With Z19 or Z20 you can update the app alone or use the matching full package to move to Z21. A device on Z21 can skip the system stage. If you have a newer bootloader or application, keep the newer version.

  1. Back up the collection

    Save a backup before updating. If migrating from SPIFFS, first complete the Raw128 backup, full source comparison and local capacity check. Storage migration is a separate step.

  2. Transfer the full package on your phone

    Save the intact ZIP to Downloads. Disconnect the file manager and open Settings → Firmware update on the LCD. In nRF Device Firmware Update for Android, choose the ZIP and pixl dfu. Keep the app open through the intermediate restart until both stages finish. The web updater supports the application-only ZIP.

  3. Check the installed versions

    After the final restart, reconnect to Pixl.js in the file manager. Expect 2.22.0-DE3.81 / App654, bootloader counter 21 with the Z21 boot region hash, and S112 7.3.0 with FWID 0x0126. The owner confirmed flashing and initial operation on one LCD. Resuming an interrupted Android system update on physical Z21 hardware still needs verification.

Archived LCD releases include their corresponding sources and requirements. DE3.80 / App653 with Z20 · DE3.75 / App648 with Z19.

Test returning to a figure and waking the device

In the file emulator or amiibo database, press the centre button while a figure is active and choose Back to File List or Back to List. Check which figure is selected. To test waking up, enable Resume app, let the device go to sleep with a figure active, then wake it.

Under Device & diagnostics, open the guided return and wake check. Record what you saw for each app. You can include diagnostic readings from before and after the checks, then save everything in one JSON file.

If you edit a draft in two tabs, you can open each saved version separately. If browser storage is unavailable, choose Save draft as JSON. Use Open a saved report to continue working on it later.

Under Compare saved device checks, choose two to eight exported reports (up to 1 MiB each). The comparison shows changes for settings that were fully recorded in both reports. You can save the result as JSON.

Take a screenshot with the LCD remote

Exit file transfer and AmiiboLink. On the awake LCD, go to Settings → Remote and select until off. Under Remote control in the file manager, choose Allmiibo DE and connect to Pixl.Remote. Use Check connection for the last response. Use Refresh screen to capture the device menu, rotate the image and save it as a PNG.

Preview figures while browsing a folder

Open a folder under Files and select a figure. On a laptop, its picture stays visible in the Selection panel as you scroll through the list. Select another figure to see its details.

Compare changes in two folders

Open the device folder under Files. Under Backup → Compare local files, choose the matching folder on your computer. After comparing, choose Save comparison reference and keep the small JSON file outside your collection. It contains paths and hashes. Use the ZIP backup to save the figure files themselves.

On your next comparison, use the same browser profile, device and folder pair, and select the saved JSON file. If both copies of a file have changed, you will see a conflict. Choose Save device copy to download its contents separately. Select the files you want to transfer to the device.

Connect a device running cylin577 PixLink

On a device running v2.27.11, choose the Pixl.js or AmiLoop Bluetooth mode. In the file manager, open Remote control, select cylin577 · PixLink, and connect. Choose Take control to send button presses. Check their effect on the device display.

Open file transfer exits the running app and releases the device buttons. If the drive does not appear, open file transfer on the device and reconnect there. cylin577 firmware release notes

If a step stops

  • The backup button is grey

    Open Files and select the root E:/ first. Connecting to a device alone does not select a folder.

  • The device does not appear

    For file management, use BLE file transfer and select Pixl.js. For updates, use Firmware update and select pixl dfu. Disconnect other browsers and phone apps using the device.

  • An application transfer was interrupted

    When pixl dfu reappears, select the same device and the same application ZIP. The web updater reads the saved position and checksum. Depending on the device's confirmed state, it resumes or starts again. For an interrupted system update, use the recovery procedure for that package in its supported client.

Programs and downloads

Use Chrome on Android or a Web Bluetooth browser such as Chrome or Edge on a laptop. The file manager itself runs in your browser. Updating the website requires no firmware flash.

iPhone and iPad

You can browse the figure catalogue and read game notes in Safari or Chrome. To connect to your Allmiibo, you need a browser with Web Bluetooth. Bluefy on the App Store provides this feature.

  1. Open the file manager in Bluefy itself. Allow Bluetooth access if iOS prompts you.
  2. Open Bluetooth file transfer on your Allmiibo. Tap Connect in the file manager, select “Pixl.js”, then open drive E:/ under Files to try reading it.

Connecting, backing up and resuming in Bluefy still need a test on a physical iPhone or iPad. For firmware updates, see the tested options for Android and the web updater for application packages.

System updates on a PC with a Nordic radio adapter

For a compatible signed system package, nRF Util supports transfers over Bluetooth LE on a PC with nrfutil nrf5sdk-tools dfu ble. This requires a separate Nordic radio adapter connected over USB, such as the nRF52840 Dongle (PCA10059) or a compatible Nordic development kit. The laptop’s built-in Bluetooth alone cannot run this procedure. For application updates you can use the web updater. For a compatible combined package on a phone, follow the Android steps.
